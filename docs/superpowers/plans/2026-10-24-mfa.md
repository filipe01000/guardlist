# MFA — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Código de aplicativo autenticador depois da senha, exigido para todos quando o administrador liga em Administração.
**Architecture:** Módulos puros em `server/mfa/` (TOTP, códigos de recuperação), um serviço com o banco (`server/mfa/service.ts`), cookie de etapa pendente em `auth.ts`, rotas em `server.ts`, e no navegador o passo do código (`MfaCode.tsx`), o cadastro (`MfaSetup.tsx`), Minha conta e Administração.
**Tech Stack:** Node 20+, `node:crypto`, `qrcode` (nova), Express, PGlite/Postgres, React 19, `node:test`.
**Spec:** `docs/superpowers/specs/2026-10-24-mfa-design.md`

## Global Constraints

- TOTP RFC 6238: SHA-1, 6 dígitos, 30 s, janela ±1, código repetido recusado (`mfa_last_step`).
- 10 códigos de recuperação, uso único, só o hash SHA-256 guardado, mostrados uma vez.
- Cookie de etapa `gl_mfa`: HttpOnly, SameSite=Lax, assinado com `SESSION_SECRET`, 5 min, contém `uid`, `ver` (session_version) e `kind` (`mfa` | `mfa-setup`).
- Erros de código contam no mesmo bloqueio da senha (`MAX_FAILED_LOGINS`, `LOCK_MINUTES`); mensagem genérica "Código incorreto.".
- Chave `MFA_SECRET_KEY` (32 bytes base64). Sem ela, não dá para ligar a exigência nem cadastrar.
- Exigência desligada: login idêntico ao de hoje. Os 109 testes atuais seguem passando.
- Commits locais, mensagem em português com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Sem push.

## Review Focus

1. **Cookie de etapa de outro usuário ou depois de trocar a senha** (versão de sessão diferente): recusado. Teste na Task 3.
2. **Administrador liga a exigência sem ter cadastro:** recusado, para não se trancar fora. Teste na Task 3.
3. **Código válido usado duas vezes no mesmo período:** recusado. Teste na Task 1.
4. **Código de recuperação com espaços, hífen ou minúsculas:** aceito do mesmo jeito. Teste na Task 1.
5. **Exigência ligada e `MFA_SECRET_KEY` removida depois:** login não pode quebrar para todos; responde com erro claro para o administrador. Teste na Task 3.

### Task 1: TOTP, códigos de recuperação e caixa de segredos

**Files:** Create `server/mfa/totp.ts`, `server/mfa/recovery.ts`, `server/secretBox.ts`; tests `server/mfa/totp.test.ts`, `server/mfa/recovery.test.ts`, `server/secretBox.test.ts`.

**Produces:**
- `base32Encode(buf: Buffer): string`, `base32Decode(s: string): Buffer`, `generateSecret(): string` (20 bytes, base32)
- `totpAt(secret: string, step: number): string`
- `verifyTotp(secret: string, code: string, nowMs: number, lastStep: number | null): number | null` (período aceito ou null)
- `otpauthUri(secret: string, account: string, issuer = 'GuardList'): string`
- `generateRecoveryCodes(): { codes: string[]; hashes: string[] }` (formato `xxxx-xxxx`, base32 minúsculo)
- `consumeRecoveryCode(hashes: string[], input: string): string[] | null` (lista sem o usado, ou null)
- `sealSecret(value: string, envKey: string, env?): string`, `openSecret(blob: string, envKey: string, env?): string`, `secretKeyAvailable(envKey: string, env?): boolean`

- [ ] Testes: vetores RFC 6238 SHA-1 (segredo ASCII `12345678901234567890`, T=59 → `287082`, T=1111111109 → `081804`, T=1234567890 → `005924`, T=2000000000 → `279037`); janela ±1 aceita, ±2 recusa; mesmo período recusado com `lastStep`; recuperação aceita `ABCD EFGH`/`abcd-efgh`, uso único; caixa de segredos ida e volta, adulterado recusado, sem chave indisponível.

### Task 2: Dados e serviço

**Files:** Modify `server/db.ts` (colunas `mfa_secret`, `mfa_pending_secret`, `mfa_enabled_at`, `mfa_last_step`, `mfa_recovery` em `users`), `server/users.ts` (`UserRow`, `PublicUser.mfaEnabled`, exportar `registerFailedAttempt(q, row)` usado também por `authenticate`); create `server/mfa/service.ts`; test `server/mfa/service.test.ts`.

**Produces** `createMfa(db: Database, opts?: { env?; now?: () => number })`:
- `available(): boolean`; `isRequired(): Promise<boolean>`; `setRequired(actor: Actor, actorId: number, on: boolean): Promise<void>` (recusa sem chave ou sem cadastro do próprio administrador); `stats(): Promise<{ enrolled: number; total: number }>`
- `startSetup(userId: number, account: string): Promise<{ secret: string; uri: string; qrSvg: string }>`
- `confirmSetup(userId: number, code: string): Promise<string[] | null>` (códigos de recuperação)
- `verify(userId: number, input: { code?: string; recoveryCode?: string }): Promise<'ok' | 'bad' | { lockedUntil: string }>`
- `regenerateRecovery(userId: number, code: string): Promise<string[] | null>`
- `disable(userId: number, code: string): Promise<boolean>` (recusa com exigência ligada)
- `reset(actor: Actor, userId: number): Promise<void>` (zera e encerra sessões)
- Auditoria conforme a spec.
